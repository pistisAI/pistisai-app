🏗️ PistisAI Service Layer Architecture

Dependency Injection & Layered Architecture

Routes Layer

Express route handlers, request/response management. Depends on services for business logic.

Middleware Layer

Auth, validation, error handling. Applied before/after route execution.

Services Layer

Business logic, domain operations. Composed via Dependency Injection, never imported directly.

Database Layer

PostgreSQL access, connection pools, migrations. Used by services only.

Utils & Auth

Shared helpers, constants, validators, error types. Imported by all layers.

🚀 Enforcement Rules

  • ✓ Routes import from Services, Middleware, Utils
  • ✓ Services import from Database, Utils, Auth (NO other services)
  • ✓ Middleware imports from Utils, Auth only
  • ✓ Database imports from Utils only
  • ✓ No circular dependencies
  • ✗ Services importing Routes
  • ✗ Services importing Middleware
  • ✗ Services importing other Services (use DI)
  • ✗ Routes importing Database directly
  • ✗ Middleware importing Services

📖 DI Pattern Example

// ✅ CORRECT: Service accepts dependencies via constructor
export class SubscriptionService {
  constructor(db, logger, emailService) {
    this.db = db;
    this.logger = logger;
    this.emailService = emailService; // Injected, not imported
  }
  
  async createSubscription(userId, planId) {
    const result = await this.db.query(...);
    await this.emailService.send(...);
    return result;
  }
}

// ✅ Routes instantiate with dependencies
import { SubscriptionService } from '../services/subscription-service.js';
import { emailQueueService } from '../services/email-queue-service.js';

const subService = new SubscriptionService(
  getPool(), logger, emailQueueService
);

router.post('/:userId/subscribe', async (req, res) => {
  const result = await subService.createSubscription(
    req.params.userId, req.body.planId
  );
  res.json(result);
});
