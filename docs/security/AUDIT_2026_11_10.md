# Secrets audit — current tree

Scope: the files on `main` at the time of writing (commit `73e01c40` plus the
changes merged after it). Tracked in issue #626. This is an audit of the
working tree; it does not rewrite git history.

## Method

A pattern scan over every text file in the repository, with matches printed
only as a hash and a length so that the audit itself does not copy anything
sensitive. Patterns covered: private-key blocks, cloud and SaaS key formats
(AWS, Google, GitHub, Slack, Stripe, Anthropic, OpenAI, Tailscale, Hugging
Face, SendGrid), JWTs, Sentry DSNs, URLs with embedded credentials, and
assignments such as `secret`, `password`, `api_key`, `token` to a
high-entropy literal. Placeholder words (`your`, `example`, `dummy`, `test`)
and low-entropy values were skipped.

Also checked by search: the word "hardcoded" in `lib/`, and literal IPv4
addresses in `lib/`, `services/`, `backend/`, `config/`, `scripts/`,
`deploy/`.

## Result

44 raw matches, all reviewed. **None is a live credential.**

| Matches | Where | What they are |
|---|---|---|
| 5 `url-credentials` | `.env.example`, `docs/backend/**` | Example database URLs with the placeholder user `user` and hosts `localhost` / `host`. |
| 10 `jwt` | `services/api-backend/services/sandbox-service.js` and its docs | Three fixed sandbox tokens. Each has a signature of 15–19 characters (a real HS256 signature is 43), so they cannot verify against any real signing key. They are fixtures. |
| 2 `private-key` | `test/powershell/TestConfig.ps1` | Key blocks whose body is the text `dummy-placeholder-do-not-use`. |
| 27 `generic-assign` | docs, tests, `lib/services/settings_preference_service.dart`, `services/api-backend/utils/logger.js`, `auth-audit-service.js` | Names of settings keys (`_hermesApiKeyKey`), log-redaction field names, audit event names, invalid-token fixtures in tests, and `"secret"` / `"token"` example values in API docs. |

The word "hardcoded" appears 7 times in `lib/`; each is a comment or a
legacy-title set, not a credential. The literal IP addresses found are
documentation examples, CIDR ranges in the SSRF protection list, and a
sample address in a UI string.

## Not covered, and what to do about it

- **Git history was not re-scanned for this document.** An earlier history
  review found credentials that were committed in the past. #583 removed
  them from the tree, but they remain in history and in the references of
  old pull requests. Treat every such credential as exposed, and rotate it
  if that has not been done. Removing them from history is a separate
  decision (it rewrites history and is not done here).
- The pattern scan finds known formats and high-entropy assignments. A
  secret in an unusual format, or one split across lines, would not be
  found.
- Binary files, and the contents of GitHub repository and Actions secrets,
  were not examined.

## Keeping it clean

The "Personal data guard" workflow (`.github/workflows/personal-data-guard.yml`,
`.gitleaks.toml`) now scans pull requests for secrets and private terms. A
finding there should block the merge; do not add an exception for a real
credential, rotate it instead.
